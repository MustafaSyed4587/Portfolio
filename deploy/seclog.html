SSH Log Threat Hunt

A Python tool that reads a server's SSH login log, finds brute-force and credential-guessing attacks, and maps each finding to the MITRE ATT&CK technique it belongs to.

The log is synthetic. I generated one week of logins for a fictional server, with four attacks hidden inside, so I could check the detector against known answers. All IP addresses come from ranges reserved for documentation. No real system was scanned or accessed.

Did it work?

Scorecard

    What I learned

    • My first version caught 3 of the 4 hidden attacks. A "low and slow" attacker, six guesses spread over a day, stayed under my 5-minute rule.
    • I added a 24-hour rule for that case, re-ran it, and confirmed it flagged nobody legitimate.
    • Thresholds are judgment calls. Too strict misses attackers, too loose buries the analyst in false alarms.

    What I would recommend

    • Turn off password sign-in for SSH and use keys, which ends most guessing attacks.
    • Disable direct root login. Attackers try "root" first.
    • Rotate the deploy credential now and review what that session did after 02:08.
    • Rate-limit and block repeat offenders automatically, for example with fail2ban.
    • Alert on success after failures. That single rule is the highest-value one here.
    • Add multi-factor authentication for any account that must use a password.
    Detection rules: brute force (10 or more failures in 5 minutes, T1110), account enumeration (5 or more usernames in an hour, T1110.003), slow guessing (5 or more failures in 24 hours, T1110.001), success after failures (T1078). Technique IDs from MITRE ATT&CK.
